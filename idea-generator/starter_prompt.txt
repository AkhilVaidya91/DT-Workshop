Build a Simple AI-Powered Idea Generator
Build a lightweight Python application using Google Gemini API and Gradio. The goal is to create a simple idea generator that gives users one randomly selected idea each time they click a button.
Keep the application minimal. This is a small, vibe-coded prototype, not a production platform. Avoid unnecessary features, complex architecture, databases, or elaborate UI components.
1. Application Overview
The application has two independent parts:
Idea Generation Script: Uses Gemini to generate a batch of 500 ideas in one API request-response cycle and saves them to a CSV file.
Gradio Web Application: Loads the CSV and randomly presents one idea to the user whenever they click a button.
The ideas should focus on simple, practical improvements to challenges faced by a first-semester NC State freshman in their daily routine. Examples could involve campus navigation, transportation, dining, academic life, social connections, time management, student resources, and everyday inconveniences.
2. Part One: Batch Idea Generation
Create a Python script called generate_ideas.py.
Requirements:
Use the Google Gemini API to generate exactly 500 distinct ideas.
Make exactly one Gemini API request for the entire batch. Do not generate ideas in multiple requests or batches.
Use a single, carefully designed prompt that asks Gemini to brainstorm a diverse collection of 500 ideas.
Each idea must contain:
title: A short, clear, one-sentence idea title.
description: Exactly three sentences explaining the idea, the problem it addresses, and how the proposed improvement could help.
Ideas should be simple, creative, practical, and understandable to beginners. They do not need to involve technology or software.
Avoid repetitive ideas, generic suggestions, and ideas that are simply variations of one another.
Ask Gemini to return structured JSON containing an array of 500 idea objects. Use Gemini's supported JSON response format where available.
Parse and validate the response. Confirm that there are exactly 500 ideas and that every idea has a title and a three-sentence description.
Save the validated ideas to ideas.csv.
Suggested CSV structure:
id
title
description
1
A Better Campus Lunch Finder
Three-sentence description...
2
Find an Available Study Space
Three-sentence description...

Use the Gemini API key from an environment variable called GEMINI_API_KEY. Do not hardcode API credentials.
The script should generate the CSV only when explicitly run. If the CSV already exists, do not overwrite it unless the user explicitly requests regeneration, such as through an --overwrite argument.
Since the requirement is to use one API request, do not silently fall back to multiple requests if Gemini cannot return the complete response. Instead, report a clear error if the response is incomplete, invalid, or truncated.
3. Part Two: Gradio Application
Create a Python application called app.py.
Core functionality:
Load all 500 ideas from ideas.csv when the application starts.
Display a clean, minimal Gradio interface.
Include a simple heading, such as "Give Me an Idea".
Include one prominent button labelled "Give Me an Idea".
When clicked, randomly select one idea from the CSV and display its title and three-sentence description.
When clicked again, display a different idea.
Use Python's random number generator to select ideas.
Maintain a list of previously displayed ideas for each user session. Do not repeat an idea until all 500 ideas have been shown in that session.
Once all ideas have been displayed, reset the available pool and allow the user to start receiving ideas again.
Display a simple message when the pool has been exhausted, or when the application is unable to load the CSV.
Use Gradio's session state to manage previously displayed ideas. There is no need for user accounts, authentication, or persistent user tracking.
4. UI and Design
Keep the interface extremely simple and clean.
The interface should contain:
A clear application title.
A short explanatory subtitle, such as "Need inspiration? Get a random idea to explore."
One button: Give Me an Idea.
An output area displaying the selected idea's title and description.
Use a minimal layout with good spacing, readable typography, and a neutral visual style. The idea should be the main focus of the interface.
Do not add navigation menus, dashboards, charts, rating systems, feedback forms, or unnecessary controls.
5. Suggested Project Structure
Organize the project as follows:
idea-generator/
│
├── app.py
├── generate_ideas.py
├── ideas.csv
├── requirements.txt
├── .env.example
└── README.md
Use .env.example to document the required environment variable without including an actual API key. Add .env and other sensitive files to .gitignore.
6. Dependencies and Setup
Use Python and the current supported Google GenAI Python SDK for Gemini.
Include the necessary dependencies in requirements.txt, such as:
google-genai
gradio
pandas
python-dotenv
The README should explain:
How to install the dependencies.
How to configure the Gemini API key.
How to generate the 500 ideas by running python generate_ideas.py.
How to launch the interface by running python app.py.
7. Important Implementation Constraints
Keep the code beginner-friendly and easy to understand.
Avoid unnecessary abstractions and overengineering.
Do not use a database. The CSV is the only data store.
Do not call Gemini when a user clicks the Gradio button. Gemini is used only in the separate batch generation script.
Do not generate ideas dynamically during application usage.
The Gradio application should work entirely from the pre-generated CSV.
Make sure the application handles missing CSV files, invalid CSV data, and API errors gracefully.
Expected Result
The final application should have a simple workflow:
Run generate_ideas.py once to generate 500 ideas using one Gemini API request.
Store all 500 ideas in ideas.csv.
Run app.py to launch the Gradio interface.
Click Give Me an Idea to receive a random idea.
Click again to receive a different idea.
Continue exploring ideas without repetition until the pool is exhausted.
Prioritize simplicity, reliability, and a clean user experience over additional features.
